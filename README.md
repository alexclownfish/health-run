# 轻跑 / 健康打卡小程序

项目分为两部分：

- `ui-prototype/`：之前完成的 H5 UI 原型，打开 `ui-prototype/index.html` 即可预览。
- `miniprogram/`：微信原生小程序源码，导入项目根目录到微信开发者工具即可运行。

## 导入方式

使用微信开发者工具打开当前仓库根目录，工具会读取 `project.config.json` 的 `miniprogramRoot` 配置。项目已配置正式 AppID，上传前需在开发者工具中登录拥有该小程序权限的微信账号。

## 已实现流程

路线首页 -> 扫描起点并开始计时 -> 依次扫描三个任务点二维码、完成动作和拍照保存 -> 扫描终点并结束计时 -> 完赛凭证。路线几何来自 2026-09-10 的 GPX 实际轨迹，约 1.56 km；图片中从右往左的标注点 `0/3/4` 对应小程序任务点 `1/2/3`。所有平台使用同一套二维码入口，也不接受任意二维码作为成功依据。

进度、起止时间、动作状态和照片路径使用本地 storage 保存。`wx.chooseMedia` 已接入真实相机/相册入口，选择后的照片通过 `wx.saveFile` 持久保存在当前手机，不会上传到自建后端或云存储，也不会跨设备同步。项目使用小程序 AppID `wx44b333d3d8cef506`。头像与昵称使用微信授权控件，记录页日历基于系统日期动态生成。

路线卡片使用微信原生 `<map>` 组件加载真实地图底图，243 个 GPX 轨迹点以 polyline 叠加显示，起点和 3 个任务点使用原生 marker。GPX 通常是 WGS84，`utils/route.js` 会在传给微信地图前转换为 GCJ-02，避免轨迹在国内底图上发生偏移。

## 点位打卡配置

小程序运行时不请求自建后端、云函数或远程校验接口。当前本地路线进度决定唯一待完成点位，二维码只能证明读取到的现场标记属于该点位。

### 点位二维码

二维码清单位于 `miniprogram/utils/qr-tags.js`，制作清单位于 `specs/002-in-app-nfc-checkin/provisioning-manifest.csv`。每个点位二维码使用纯文本格式：

```text
HRQ1|001|QR-001-A|<随机token>
```

二维码应印在起点、三个任务点和终点标牌上。所有平台用户先打开小程序，再点击“扫码打卡”。二维码不使用 URL，不负责自动打开小程序。起点只在未开始时接受，终点只在三个任务点完成后接受。二维码可以被拍照复制，因此只适用于当前低风险活动。

起点编号为 `000`，三个任务点仍为 `001`、`002`、`003`，终点为 `999`。原三个任务点二维码原文不变。完整制作原文参见 `specs/004-start-finish-qr-timing/qr-payloads.md`。

总用时 = 终点扫码时间 - 起点扫码时间，格式为 `HH:mm:ss`，包含行进、动作、拍照和停留时间。关闭页面不暂停计时，重复扫码不修改时间；第三个任务点完成时仍在计时，不会直接生成凭证。时间取自手机时钟，不具备可信成绩或防改时能力。

新流程使用 `patchwalk-progress-v3`，需要从起点重新开始。旧 `v2` 记录不删除、不混入新成绩，旧存储中的照片仍保留；新页面不展示旧进度。

本方案只提供本机层面的防误用校验。二维码和本地 storage 都不能提供密码学防伪或可信考勤能力；清除小程序数据、重装或更换设备会丢失进度。
